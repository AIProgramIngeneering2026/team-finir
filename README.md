# VulnScout

Сервис проверки зависимостей проекта на известные уязвимости (CVE).
Принимает манифест зависимостей (`go.mod`, `package-lock.json`), находит пакеты с известными
уязвимостями по базе [OSV.dev](https://osv.dev) и возвращает отчёт: что уязвимо, насколько критично
и до какой версии обновиться.

## Какую проблему решаем

В типичном Go- или JS-проекте десятки прямых и транзитивных зависимостей. Уязвимости в них
публикуются постоянно, а вручную сверять каждую версию с базами CVE никто не будет. В итоге
уязвимая библиотека спокойно доезжает до продакшена.

VulnScout делает эту проверку одним запросом к API — вручную перед релизом или автоматически
на каждый PR в CI.

## Для кого

| Пользователь | Что делает |
|---|---|
| **Разработчик** | Загружает манифест перед релизом, смотрит отчёт и версии с исправлением |
| **CI-пайплайн** | Вызывает API на каждый PR и роняет сборку, если найдены уязвимости выше порога |
| **Тимлид / безопасник** | Смотрит историю сканов по проекту, перезапускает устаревшие отчёты |

## Как это работает

```
манифест ─► POST /v1/scans ─► Job (скан) ─► Dispatcher (воркер)
                                               ├─ Registry → Parser (go.mod | package-lock.json)
                                               ├─ VulnSource (OSV.dev | fake) — поиск уязвимостей
                                               └─ findings → отчёт: GET /v1/scans/{id}
```

Скан выполняется асинхронно и проходит состояния
`created → parsing → querying → enriching → done / partial / failed / cancelled`.
Подробно — в [docs/requirements.md](docs/requirements.md).

## Что входит в систему

- REST API с контрактом OpenAPI: создание скана (идемпотентно), статус и отчёт, отмена, история по проекту
- Разбор манифестов: `go.mod` и `package-lock.json` за единым контрактом `Parser`
- Поиск уязвимостей в OSV.dev через адаптер: timeout, ограниченный retry, fake для тестов
- Хранилище с миграциями: PostgreSQL к практике 7
- Логи с correlation ID, health check, конфигурация из окружения
- Запуск одной командой: `docker compose up`

## Что точно не входит

- Клонирование репозиториев и сборка кода — работаем только с файлом-манифестом
- Сканирование сети, хостов, контейнерных образов и бинарников
- Собственная база уязвимостей — данные берём из OSV.dev
- Автоматическое исправление зависимостей и создание PR
- Пользовательский интерфейс и учётные записи пользователей

## Стек

Go 1.26, PostgreSQL, `goose` (миграции), `testing` + testcontainers-go, GitHub Actions, Docker Compose.
