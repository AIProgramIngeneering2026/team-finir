# Проверка контракта колодой

Контракт: [openapi.yaml](api/openapi.yaml), [контракт Tool](tool-contract.md),
[диаграмма состояний](architecture.md#3-диаграмма-состояний-скана-job), ADR в [docs/adr](adr/).

| Карта | Ответ контракта |
|---|---|
| **К1 Двойной клик** | Повтор `POST /v1/scans` с тем же `Idempotency-Key` → `200` с прежним `id`, заголовок `Idempotent-Replayed: true`; два одновременных запроса создают один скан — `openapi.yaml`, `POST /v1/scans`; [ADR-0002](adr/0002-idempotency-key.md). Без ключа каждый запрос создаёт скан — это явно записано там же |
| **К2 Ответ потерялся** | Клиент повторяет запрос с тем же `Idempotency-Key` и получает уже созданный скан — `openapi.yaml`, `POST /v1/scans`, ответ `200`. Без ключа скан можно найти в истории `GET /v1/scans?project=` |
| **К3 Неизвестная операция** | Операция у нас одна — скан; аналог неизвестной операции — неподдерживаемый формат файла: `400 unsupported_manifest` со списком форматов в `details.supported`, скан не создаётся — `openapi.yaml`, `POST /v1/scans`, ответ `400` |
| **К4 Кривые параметры** | Нет `project` или `file`, неверный формат `project` → `400 invalid_params`, имя поля в `details.field`; неверный `limit` в истории → `400 invalid_params` — `openapi.yaml`, схема `Error`, ответы `400` |
| **К5 Воскрешение** | Перезапустить завершённый скан нельзя: `done`, `partial`, `failed`, `cancelled` — конечные. Проверить ещё раз — новый скан через `POST /v1/scans`, прежний отчёт остаётся в истории — [architecture.md, запрещённые переходы](architecture.md#запрещённые-переходы) |
| **К6 Отмена** | `POST /v1/scans/{id}/cancel` → `202`; скан в `created` отменяется сразу, выполняющийся дорабатывает и переходит в `cancelled` без отчёта; завершённый → `409 scan_finished` — `openapi.yaml`, `cancelScan`; [ADR-0003](adr/0003-cancel-without-interrupt.md) |
| **К7 Огромный вход** | Файл больше 1 МБ отклоняется до создания скана: `413 manifest_too_large`, лимит в `details.max_bytes` — `openapi.yaml`, `POST /v1/scans`, ответ `413`. Внутри лимита большой `package-lock.json` отправляется в OSV.dev пачками — [tool-contract.md, OSVClient](tool-contract.md#реализация-1-osvclient--osvdev) |
| **К8 Чужой или несуществующий id** | Несуществующий → `404 scan_not_found` — `openapi.yaml`, ответ `ScanNotFound`. Чужих сканов сознательно не различаем: авторизации нет, идентификаторы — случайные UUID — [ADR-0004](adr/0004-no-auth-uuid-ids.md) |
| **К9 Перезапуск сервера** | При запуске сканы в `parsing`, `querying`, `enriching` возвращаются в `created` и обрабатываются заново; после трёх попыток — `failed` с ошибкой `worker_lost` — [ADR-0001](adr/0001-one-process-background-scans.md); [диаграмма состояний](architecture.md#3-диаграмма-состояний-скана-job), служебный переход |
| **К10 Внешний сервис** | OSV.dev молчит — таймаут и ограниченные повторы; отвечает мусором или переименовал поле — ответ без обязательных полей считается ошибкой источника. Часть пакетов не проверена → `partial` со списком в `unchecked`, не проверен ни один → `failed` с ошибкой `vuln_source_unavailable` — [tool-contract.md, VulnSource](tool-contract.md#tool-2-vulnsource); `openapi.yaml`, схемы `Scan` и `UncheckedPackage` |

## Что предложил ИИ

**Модель:** Claude.

**Промпт:**

> Ты атакующий в упражнении «контрактный покер». Вот контракт сервиса VulnScout: OpenAPI, контракт Tool,
> диаграмма состояний и ADR (приложены). Мы уже прошли колодой К1–К10: двойной клик, потерянный ответ,
> неизвестная операция, кривые параметры, воскрешение, отмена, огромный вход, чужой id, перезапуск сервера,
> внешний сервис. Найди ещё 3 ситуации, на которые контракт не отвечает или отвечает плохо.
> Для каждой: конкретный запрос, что пойдёт не так, как закрыть.

### Находка 1. Бесконечная история

**Предложение ИИ:** у проекта, который проверяется на каждый коммит, за год набираются десятки тысяч сканов.
`GET /v1/scans?project=` без ограничений отдаст их все одним ответом: долгий запрос к БД и огромный JSON.

**Решение:** принято.

**Что изменили:** в `GET /v1/scans` добавили `limit` (по умолчанию 20, максимум 100) и `cursor`,
в ответе — `next_cursor`.

### Находка 2. Лимит запроса к OSV.dev

**Предложение ИИ:** `package-lock.json` размером меньше 1 МБ может содержать несколько тысяч пакетов.
Если отправить их одним запросом `querybatch`, OSV.dev может отклонить запрос как слишком большой,
и весь скан уйдёт в `failed`, хотя источник доступен.

**Решение:** принято.

**Что изменили:** в контракте `OSVClient` записали, что пакеты отправляются пачками; отказ одной пачки
делает скан `partial`, а не `failed`.

### Находка 3. Частый опрос статуса

**Предложение ИИ:** CI опрашивает `GET /v1/scans/{id}` в цикле без паузы, сотни запросов в секунду.
Контракт не ограничивает частоту запросов и не подсказывает клиенту, когда спрашивать снова.

**Решение:** не принято.

**Почему:** сервис внутренний и без авторизации ([ADR-0004](adr/0004-no-auth-uuid-ids.md)), ограничивать
частоту не по чему. `GET` по первичному ключу дешёвый. В описание `GET /v1/scans/{id}` добавили рекомендацию клиенту
опрашивать не чаще раза в 2 секунды. Вернёмся к вопросу вместе с авторизацией.
