# ADR-0004. Без авторизации, идентификаторы сканов — UUID

**Дата:** 2026-11-08
**Статус:** принято

## Контекст и ограничения

- Учётные записи пользователей не входят в границы системы (README).
- Сервис запускается внутри команды или в её CI, а не как публичный сервис.
- Отчёт содержит список зависимостей и уязвимостей проекта: это не секрет, но и не то, что стоит отдавать кому угодно.

## Решение

- Авторизации в первой версии нет.
- Идентификатор скана — случайный UUID v4: перебором чужой скан не найти.
- Несуществующий скан → `404 scan_not_found`. Отдельного понятия «чужой скан» нет: любой, кто знает
  идентификатор, видит скан.
- История `GET /v1/scans?project=` доступна по имени проекта.

## Рассмотренные альтернативы

| Альтернатива | Почему нет |
|---|---|
| API-ключ на проект | нужно выдавать и хранить ключи, ротация; для внутреннего сервиса преждевременно |
| Последовательные номера сканов | перебором видны все сканы |
| OAuth / учётные записи | вне границ системы |

## Цена решения

- Любой в сети, где развёрнут сервис, может читать историю проекта по его имени и отменять сканы
  по известному идентификатору.
- Область действия Idempotency-Key — `project`, а не клиент (ADR-0002).

## Условия пересмотра

- Сервис станет доступен вне команды или появятся приватные проекты → API-ключ на проект:
  чужой скан будет отвечать так же, как несуществующий, `404`.
