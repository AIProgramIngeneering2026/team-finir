# ADR-0001. Один процесс, скан выполняется в фоне

**Дата:** 2026-11-08
**Статус:** принято

## Контекст и ограничения

- Скан ходит в OSV.dev: на большом манифесте это десятки запросов, от секунд до десятков секунд.
  Если OSV.dev отвечает медленно, время растёт до таймаута и повторов.
- Клиенты — люди и CI. HTTP-клиенты и прокси обрывают соединение через 30–60 секунд.
- Нужны отмена скана и частичный результат (`partial`).
- Команда маленькая, запуск должен быть одной командой (`docker compose up`).

## Решение

Один Go-процесс, внутри — HTTP API и пул воркеров (горутины). `POST /v1/scans` сохраняет скан
в состоянии `created` и сразу отвечает `202`. Воркер забирает скан из хранилища и ведёт его по состояниям.
Очередью служит таблица сканов: воркер атомарно берёт следующий скан в `created`.

При запуске сервиса сканы в промежуточных состояниях (`parsing`, `querying`, `enriching`) — это сканы,
которые обрабатывал остановленный процесс. Они возвращаются в `created`, счётчик попыток увеличивается;
после трёх попыток скан переходит в `failed` с ошибкой `worker_lost`.

## Рассмотренные альтернативы

| Альтернатива | Почему нет |
|---|---|
| Синхронный ответ: скан выполняется внутри HTTP-запроса | упирается в таймауты клиентов; нет состояний, отмены и `partial`; повтор после обрыва запускает работу заново |
| Отдельные сервисы API и воркер | два процесса, общая очередь и деплой; для нашей нагрузки выигрыша нет |
| Брокер сообщений (Kafka, RabbitMQ) как очередь | ещё один сервис в `docker compose`; состояние скана всё равно хранится в БД, получится две системы правды |
| Отдельный воркер на каждый этап | промежуточные результаты нужно сохранять и передавать между воркерами; этапы короткие, выигрыша нет |

## Цена решения

- Клиент должен опрашивать `GET /v1/scans/{id}`, чтобы узнать результат.
- API и воркеры масштабируются только вместе.
- Возврат сканов в очередь при запуске корректен, пока процесс один: при двух экземплярах один из них
  вернул бы в очередь сканы, которые обрабатывает другой.

## Условия пересмотра

- Нужно больше одного экземпляра сервиса → вместо возврата при запуске — аренда скана
  с продлением (heartbeat) и возврат просроченных.
- Воркеры начинают мешать API по ресурсам → выносим воркер в отдельный процесс; контракты Parser,
  VulnSource и Store при этом не меняются.
