# ADR-0002. Защита от повторного создания скана — Idempotency-Key

**Дата:** 2026-11-08
**Статус:** принято

## Контекст и ограничения

- Клиент может отправить `POST /v1/scans` дважды: двойной клик, повтор после таймаута, перезапуск пайплайна CI.
- Лишний скан — это лишние запросы к OSV.dev и запись в истории, которую клиент не создавал.
- Повторная проверка того же манифеста позже — законная операция: за это время могли появиться новые CVE.
- Авторизации нет, поэтому нельзя привязать ключ к клиенту.

## Решение

Необязательный заголовок `Idempotency-Key` (до 255 символов). Ключ действует 24 часа в рамках `project`.

- Новый ключ → скан создаётся, `202`.
- Повтор с тем же ключом и тем же телом → `200` с существующим сканом и его текущим состоянием,
  заголовок `Idempotent-Replayed: true`.
- Тот же ключ с другим телом → `422 idempotency_key_reused`. Тело сравнивается по SHA-256
  от имени файла и содержимого манифеста.
- Без ключа каждый запрос создаёт новый скан.

Скан и ключ записываются в одной транзакции, уникальность обеспечивает индекс `(project, key)`.
Два одновременных запроса с одним ключом создают один скан: второй ждёт первую транзакцию и получает её результат.

Для CI рекомендован ключ `<проект>:<коммит>:<путь к манифесту>`.

## Рассмотренные альтернативы

| Альтернатива | Почему нет |
|---|---|
| Дедупликация по хешу манифеста без ключа | запрещает законную повторную проверку того же файла; клиент не может явно попросить новый скан |
| Хранить ключи в Redis | ещё один сервис; запись ключа и скана нельзя сделать одной транзакцией |
| Сначала `SELECT`, потом `INSERT` | два запроса за 100 мс оба пройдут проверку и создадут два скана |
| Обязательный ключ, как в платёжных API | неудобно для разработчика с `curl`; лишний скан стоит недорого, в отличие от двойного платежа |

## Цена решения

- Отдельная таблица ключей и фоновая очистка ключей старше 24 часов.
- Клиент без ключа не защищён от дублей — это его выбор.
- Область действия ключа — `project`, а не клиент: два клиента с одинаковыми `project` и ключом получат один скан.

## Условия пересмотра

- Появится авторизация → область действия ключа меняется с `project` на клиента.
- Повторы станут дорогими (например, платный источник уязвимостей) → ключ становится обязательным.
